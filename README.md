# 한국 예능형 자막 자동 생성 시스템 제안서

한국 예능 스타일(재치 있는 말맛·밈·의성어/의태어·강조 타이포그래피)을 자동으로 입히는 자막/오버레이 시스템을 위한 설계안이다. 목표는 **AI 티가 덜 나고 실제 예능 편집자가 만든 듯한 자막**을 빠르게 뽑아내는 것이다.

## 1. 제품 목표와 원칙
- **AI스럽지 않게**: 산문형 번역투 금지, 구어체와 밈/의성어를 적극 사용하고 길이를 짧게 유지.
- **상황 몰입감**: 화자의 감정·제스처·컷 전환을 모두 반영해 자막 위치·색·애니메이션을 다르게 설정.
- **한국 예능 톤**: 인기 프로그램(런닝맨, 무한도전, 나 혼자 산다 등)의 말풍선·밈 패턴을 벤치마크하고 사전 템플릿화.
- **편집자 친화**: 최종 번인 영상 + 수정 가능한 메타데이터(ASS/JSON/Lottie) 동시 제공.

## 2. 데이터 수집·라벨링 전략
- **소스**: 공개 클립/하이라이트 영상 → OCR로 기존 예능 자막 추출 후 ASR과 정렬.
- **라벨**: 감정(기쁨/당황/분노/진지/웃참), 연출 타입(말풍선/충격/속닥/내레이션), 컬러·폰트·애니메이션, 밈/의성어 토큰.
- **전처리**: 욕설/민감 표현 필터링, 자막 중복 제거, 컷 단위로 시간 보정.
- **평가 세트**: 프로그램별 톤을 대표하는 1~2분 클립을 골라 정답 라벨과 비교.

## 3. 모델 파이프라인
1) **오디오**: FFmpeg로 분리 → 잡음 제거 → Whisper(ko)로 ASR → Pyannote로 화자 분리/구간화 → prosody 추출(음 높이·세기·속도).  
2) **비디오**: 얼굴/신체 바운딩 박스(Detectron/OpenPose), 표정/동작 감정(EmotionNet), 장면 전환(TransNetV2), 화면 내 텍스트 OCR.  
3) **스타일 의사결정 엔진**:
   - 규칙 + LLM 하이브리드.
   - 입력: 대사, 화자 ID/감정, prosody(강세·속도), 비주얼 이벤트(놀람 표정, 뛰는 동작), 장면 전환 여부.
   - 출력: 축약/변형 대사, 밈/의성어 삽입, 스타일 토큰(색·폰트·테두리·애니메이션·위치·레이어).
4) **위치/레이어링**: 얼굴/주요 객체를 피해서 안전 영역에 배치, 화면 텍스트와 겹치지 않도록 우선순위 정렬.
5) **렌더링**: ASS/SSA + FFmpeg 번인, 또는 After Effects/Lottie 템플릿에 메타데이터를 주입해 애니메이션 적용.
6) **프로그램 대본·전용 용어/스타일 인지**: 방송사/PD가 제공한 예능 대본(기본 MC 멘트·룰 정도만 있어도 됨)에서 **인물 이름·별칭·팀명·나이/연령대·전용 용어·스코어보드 항목**만 추출해 `program_lexicon`으로 만들고, 프로그램별 **자막 디자인 폼(JSON/스타일 가이드)**을 `caption_theme`으로 로드해 엔진에 주입.

## 4. 예능형 스타일 가이드(샘플 규칙)
- **톤/길이**: 2줄 이하, 8~14자/줄. 평어체, 줄임말, 반복(ㅋㅋㅋ, 헉헉) 허용. 
- **색상**: 감정 매핑 예) 분노=레드+볼드+진동, 당황=시안+흔들림, 기쁨=옐로+팝업, 진지=화이트+얇은 테두리. 
- **특수 연출**: 
  - 놀람 표정+높은 피치 → `"(동공지진)"` 말풍선+줌/펄스. 
  - 웃참 실패 → `"터짐"`/`"푸학"` 배경 폭발 GIF 또는 스케일업. 
  - 리액션 컷(관찰자) → 작은 말풍선, 투명도 높여 겹치기. 
- **밈 사전 관리**: 시대별/프로그램별 밈 토큰 리스트를 버전 관리하고 LLM 프롬프트에 포함(예: `"이게 되네"`, `"(망함)"`, `"출발~"`).

## 5. LLM 프롬프트/제약 예시
```
역할: 한국 예능 자막 작가. 대사를 2줄 이하로 짧게, 구어체/의성어·밈을 섞어 유머러스하게 변형한다.
규칙: 길이 8~14자/줄, 존댓말 금지, 번역투 금지, 욕설·비방 필터. 감정 태그와 prosody를 반영해 강조 위치를 결정.
출력: {text, style_token, emphasis_word}
```
- **휴리스틱**: `emphasis_word`는 prosody 최고 피치/에너지 구간을 우선 선택.
- **안전 필터**: 금지어 리스트, 정치/혐오/개인정보 탐지 후 무해한 표현으로 치환.

### 5-1. 자막 타입 라우팅 프롬프트(말/상황/재미)
```
역할: 컷 단위로 자막 타입을 결정하는 한국 예능 PD.
입력: [화자 대사], [장면 설명], [감정·동작 태그], [컷 종류(주요/리액션/상황)], [필요 시 맥락 요약].
결정 규칙:
- 말자막: 또렷한 발화가 있고 정보 손실 없이 전달해야 할 때. 화자 감정과 prosody를 반영해 강조.
- 상황자막: 대사가 없거나 묵음, 혹은 행동/상황이 핵심일 때. 동작·표정·배경 이벤트를 서술형/의태어로 표현.
- 재미자막: 상황 대비 아이러니/과장이 웃음 포인트일 때. 밈, 비유, 과장된 표현을 짧게 삽입(불편·비방 금지).
출력: {subtitle_type: 말|상황|재미, rationale, safety_notes}
```
- **타입별 스타일 지시어**: 말자막=깔끔/가독 우선, 상황자막=화면 한쪽에 작게, 재미자막=컷 중심에 큰 크기+색 대비.

### 5-2. 재미자막 생성 프롬프트(예: 숨바꼭질 장면)
```
역할: 30년 차 한국 예능 작가. 장면의 웃음 포인트를 짧고 재치 있게 적는다.
입력: [장면 요약: '숨바꼭질, 맏형이 숨느라 힘들어함'], [금지어 리스트], [톤: 재치/따뜻함/가벼운 자조], [길이: 8~14자].
스타일: 사람 말투, 번역투 금지, 공격적 표현 금지. 생동감 있는 비유/의태어 사용.
출력 예시: "나이를 잊은 생존의 몸부림", "관절 아슬아슬 폭주", "장난감 숨기는 맏형 ON" 등 1~2개 제안.
```

### 5-3. 워드 파일 자막 산출 규격(폰트/정렬/톤 매핑)
- **출력 형식**: `.docx` 내 각 자막을 한 문단으로 기록. 시간 코드·메타데이터는 숨김 필드/코멘트로 남겨 편집자가 확인 가능.
- **폰트/정렬 룰**(예능 톤 기준):
  - `고딕` (기본 좌측): 말자막/정보 전달용. 예) `1라운드를 향한 기묘한... 첫 걸음`.
  - `고딕 중앙` (중앙 정렬, 중간 크기): 분위기 전환·컷 타이틀. 예) `낯선 세계 그 첫 번째 관문!`.
  - `중앙대판` (대형, 중앙): 회차/라운드/결전 등 메인 타이틀. 예) `결전의 서막`.
  - `굴림` (기본/작게, 좌측 또는 우하단): 속마음·쪽글·속삭임·상황 메모. 예) `(로그인이 완료되었습니다)`.
- **문장부호**: `?`, `!`, `...`, 말줄임·괄호·느낌표 자유 사용. 단, 과도한 반복·과격 표현 금지.
- **스타일 토큰 → 워드 스타일 매핑 예시**:
  - `{subtitle_type: "말", tone: "깔끔", emphasis: true}` → 스타일 `고딕` + 볼드 + 노란 하이라이트.
  - `{subtitle_type: "상황", tone: "조용"}` → 스타일 `굴림` + 이탤릭 + 투명도 메모(주석).
  - `{subtitle_type: "재미", tone: "밈"}` → 스타일 `고딕 중앙` 또는 `중앙대판`, 색상 대비(빨강/노랑) + 그림자.
- **워드 생성 프롬프트 예시** (LLM이 자막 문구를 고르고 워드 스타일을 지정):
```
역할: 한국 예능 편집 어시스턴트. 입력된 자막 후보 리스트를 받아 워드 문단으로 내보낸다.
출력 형식: [{text, font: 고딕|고딕 중앙|중앙대판|굴림, align: left|center, size: small|medium|large, notes(선택): 강조/색/애니메이션 힌트} ...]
규칙:
- 대사 전달은 고딕, 속마음/속삭임/환경음은 굴림, 컷 타이틀·재미 강조는 고딕 중앙/중앙대판을 우선 선택.
- 글자수 8~14자, 번역투 금지, 사람처럼 짧고 생동감 있게. 필요 시 `?`나 `...`로 여운 표현.
- 안전 필터: 비방·혐오·나이/외모 조롱 금지. 과장·비유는 따뜻하고 가벼운 톤으로.
예시 입력: {subtitle_type: "재미", text: "나이를 잊은 생존의 몸부림", emotion: "허둥", scene: "숨바꼭질 맏형"}
예시 출력: [{text: "나이를 잊은 생존의 몸부림", font: "고딕 중앙", align: "center", size: "medium", notes: "노랑+팝업"}]
```

### 5-4. 프로그램 대본·용어·인물 정보 활용 프롬프트
```
역할: 프로그램 전용 용어/인물 정보를 보정하는 한국 예능 리서처.
입력: [ASR/화자 추정 결과], [program_lexicon: 이름·별칭·팀명·나이/연령대·전용 용어], [PD 가이드 자막(선택)], [OCR/스크린 텍스트(선택)].
규칙:
- ASR/화자 토큰을 lexicon과 레벤슈타인·음운 유사도로 정렬하고, **이름/나이/역할**이 불확실하면 `(?)` 표시 후 notes에 근거를 남긴다.
- 예능 대본에만 있는 용어라면 그대로 보존하되, 맥락상 오역 가능성이 있는 경우 원문/대체안 둘 다 notes에 기재.
- PD 가이드 자막에 등장하는 인물/용어는 우선 순위로 확정하고, 발견되지 않은 lexicon 엔티티는 "추가 메모"로 상황자막에 보조 표기.
출력: {canonical_name, alias?, age_or_range?, team?, program_term?, confidence, notes}
```

### 5-5. 프로그램별 자막 디자인 폼 적용 절차
- **입력**: `caption_theme` JSON (폰트명·크기·정렬·테두리·그림자·색상 팔레트·레이어 규칙) + `tone_pack`.
- **적용 순서**: (1) PD 제공 테마를 우선 적용 → (2) tone_pack의 톤/밈/색상 팔레트 병합 → (3) 기본 프리셋으로 폴백.
- **프롬프트 힌트**: 자막 생성 시 `{subtitle_type, tone_pack, caption_theme.style_id}`를 함께 넘겨 **프로그램 고유 레이아웃**(예: 특정 코너의 스코어보드 색·폰트)을 강제.
- **검증**: 렌더 전에 각 문단에 `theme_applied=true/false`를 기록하고, 테마 누락 시 fallback 이유를 notes에 남겨 수동 교정이 가능하게 한다.

### 5-6. PD 가이드 자막 보존 & 빌드업 연출 프롬프트
```
역할: 한국 예능 수석 편집자. PD가 미리 심어둔 가이드 자막을 최대한 보존하면서 장면 흐름에 맞춰 빌드업되는 자막 시퀀스를 만든다.
입력: [컷 단위 자막 후보 {text, subtitle_type, start/end}], [PD 가이드 자막 {text, priority}], [장면 순서/서사 태그], [쇼츠 여부].
규칙:
- PD 가이드 자막은 priority=high인 경우 문구·배치·폰트를 그대로 유지하고, 필요 시 시간 코드만 정제. priority=mid는 의미를 유지하되 길이·톤만 다듬어도 된다.
- 컷 시퀀스 내 빌드업: 같은 상황이 반복/고조될 때 단어·색·크기를 점진적으로 키워서 연결감 부여. (예: "숨어라" → "아직 못 찾음" → "숨은 자 vs 찾는 자" → "결전의 서막")
- 쇼츠/하이라이트용이면 첫 3초에 핵심 메시지(훅)를 배치하고, 후반부에 리마인더/CTA 자막(구독/다음 편 예고)을 작게 배치.
- 자막 흐름 테스트: 동일 인물/상황에 대한 자막은 동일 톤·색을 유지해 '따로 노는' 느낌을 방지하고, 컷 전환 시 동일 키워드를 반복해 리듬을 만든다.
출력: [{text, font, align, size, notes, keep_original(bool), sequence_tag}] ...
```

### 5-7. 빌드업 시퀀스 템플릿(장르 불문 공통 규칙)
- **장르 중립 원칙**: 숨바꼭질 예시가 아닌 모든 예능(리얼리티/토크/게임/연애/먹방/오디션/여행)에서 재사용할 수 있는 패턴으로 설계한다. 장면 구조만 입력 바꾸면 적용되도록 `sequence_tag`와 `tone_pack`을 별도 관리한다.
- **공통 단계**: `intro → build → peak → payoff` 4단계를 강제하고, 각 단계마다 색·크기·폰트 강도를 점진적으로 상승.
- **톤 팩(Tone Pack)**: 프로그램이나 에피소드별로 `tone_pack`을 로드해 장르/콘셉트에 맞는 밈·어휘·색상 팔레트를 주입한다. 예)
  - `tone_pack: 런닝게임` → 러닝/추격, 스코어보드, 호흡/스피드 의태어.
  - `tone_pack: 토크/인터뷰` → 한 줄 핵심, MC 리액션, 꼬리 질문 강조.
  - `tone_pack: 연애` → 미묘한 표정, 관계 변화 키워드, 심장/두근 의성어.
  - `tone_pack: 먹방` → 맛/식감 의태어, 음식 클로즈업 시 색 대비, 냄새/바삭 표현.
  - `tone_pack: 오디션/경연` → 긴장/심사 포인트, 점수/순위 UI, 멘토 코멘트 말풍선.
- **시퀀스 설계 예시(입력만 교체해 재사용)**: 동일 키워드/색/톤을 이어가면서 크기·강조를 키워 흐름을 만든다.
  1) **컷1(intro)** — `굴림`, 좌측: `(상황 시작 메모)` / `sequence_tag: intro`
  2) **컷2(build)** — `고딕`, 좌측: `상황 진행/준비` / `sequence_tag: build`
  3) **컷3(build)** — `고딕 중앙`, 중앙: `웃음 포인트·갈등 고조` / `sequence_tag: build`
  4) **컷4(peak)** — `고딕 중앙`, 중앙: `정점 직전의 질문/반전` / `sequence_tag: peak`
  5) **컷5(payoff)** — `중앙대판`, 중앙 대형: `결과/리액션` + 보조 리액션은 `굴림` 말풍선 / `sequence_tag: payoff`
- **훅/리마인더**: 쇼츠면 컷2~3에 `hook=true` 메모, 컷5에 `CTA` 메모(작게 배치)로 후반 리마인더 추가. 본편이면 hook/CTA는 선택.
- **자동 검수**: 동일 `sequence_tag`끼리 색상·폰트 일관성을 강제하고, 컷 전환 간 키워드가 1개 이상 반복되는지 확인. `tone_pack`별 금지어/허용 밈 리스트도 확인.

#### 5-7-1. 빌드업 프롬프트(장르 전환 지원)
```
역할: 한국 예능 수석 편집자. 입력된 컷 리스트를 받아 장르/콘셉트에 맞는 빌드업 시퀀스를 생성한다.
입력: [컷 {scene_summary, dialogue?, emotion, action}], [subtitle_type 후보], [tone_pack], [PD guide], [쇼츠 여부].
규칙:
- tone_pack에 정의된 색/폰트/밈 사전을 우선 사용하고, 없으면 기본 팔레트로 폴백.
- 컷 간 키워드/어휘를 재사용해 서사 연결. 같은 인물/팀은 동일 색/폰트를 유지.
- 빌드업 4단계를 채우고, 부족하면 리액션/환경음으로 메꿔 리듬 유지.
- 장르별 금지어/톤(예: 연애=비하 금지, 오디션=참가자 배려)을 필터링.
출력: [{text, font, align, size, sequence_tag, subtitle_type, tone_pack, notes} ...]
```

### 5-8. 자동 검수/품질 체크 프롬프트(페르소나 심층 리뷰용)
``` 
역할: 30년 차 예능 PD, 베테랑 예능 작가, 일반 시청자 세 페르소나가 순차로 검수한다.
입력: 워드 자막 [{text, font, align, size, notes, sequence_tag, hook?, CTA?}], 영상 요약/컷 리스트, PD 가이드 자막.
검수 공통 규칙:
- AI틱한 번역투/장문 금지(8~14자 기준), 밈 과용 금지, 공격적 표현·조롱·차별 필터링.
- 컷 리듬: 동일 인물/상황은 색·톤·폰트가 유지되는지 확인, 빌드업 단계(`intro→build→peak→payoff`)가 누락되지 않았는지 체크.
- PD 가이드 자막: priority=high는 텍스트/폰트/정렬 모두 보존되었는지, mid는 의미 유지+톤만 다듬었는지 확인.
출력: {persona: PD|Writer|Viewer, issues: [...], quick_fixes: [...], pass/fail} 3개를 병렬 출력하고, fail 항목이 있으면 수정 제안까지 제공.
```

### 5-9. 워드 파일 템플릿/메타데이터 필수 항목
- **스타일 프리셋**: `고딕/고딕 중앙/중앙대판/굴림`을 워드 스타일로 사전 정의(폰트명·크기·정렬 포함) 후 LLM은 스타일 이름만 지정.
- **메타 필드**: 각 문단에 `data-subtitle-type`, `data-sequence-tag`, `data-hook`, `data-CTA`, `data-keep-original` 커스텀 속성을 코멘트/숨김 필드로 기록해 후처리 자동화.
- **테마 추적**: 적용된 `caption_theme.style_id`와 `tone_pack`을 메타 필드에 함께 남겨, 프로그램 전용 자막 폼이 실제로 사용됐는지 확인 가능하게 함.
- **레이아웃 규칙**: 기본 상하좌우 6% 세이프 존, 얼굴/객체 바운딩 박스와 겹치면 `notes`에 위치 이동 힌트(예: `우상단`, `중앙 하단`)를 남김.
- **PD 가이드 유지 플래그**: priority=high 문구는 `keep_original=true`를 기록하고, diff를 함께 남겨 사람이 빠르게 비교 가능하게 함.
- **숫자/문장부호**: `?`, `!`, `...`, 괄호는 허용하되 한 문단에 2개 이하로 제한해 과잉 연출을 방지.

## 6. 평가와 튜닝
- **정량**: WER/CER(ASR), 타이밍 오차(ms), 자막 겹침률, 안전 영역 침범률.
- **정성**: A/B 테스트(사람 평가: 재미/몰입/방해 여부), 편집자 수정 시간.
- **오류 패턴 학습**: 과하게 AI스러운 표현, 장황한 자막, 감정 미스매치 사례를 수집해 프롬프트/규칙을 보정.

### 6-1. 페르소나 3단 검수 체계
- **30년 차 예능 PD**: 맥락/톤 점검 — 자막이 프로그램 콘셉트와 흐름을 해치지 않는지, 컷 리듬을 살리는지 확인.
- **베테랑 예능 작가**: 문장/유머 품질 — 말맛, 밈 적합성, 불편 요소(비방/혐오/나이/외모 조롱) 여부 점검.
- **일반 시청자**: 가독/방해 여부 — 화면 가림, 길이, 정보 과잉, 몰입 저해 요소 확인.
- **워크플로우**: 자동 생성 → LLM 페르소나별 리뷰 프롬프트 → 수정 권고 취합 → 최종 자막(텍스트/ASS/JSON) 출력. 최종 산출물은 텍스트 파일로도 제공해 편집 호환성 확보.

## 7. 운영·배포
- 비동기 파이프라인(오디오/비디오 분리 처리) + GPU 배치. 
- 캐싱(중복 장면 분석 방지), 큐(Celery/Kafka), 프로파일링으로 10~20분 영상 처리 시간 단축. 
- 웹 미리보기(React/Canvas)로 자막 위치 드래그 & 다시 렌더. 

## 8. 확장 로드맵
- **단기**: Whisper+규칙 기반 스타일 → ASS 렌더링 MVP. 
- **중기**: LLM 스타일러 + 밈 버전 관리 + 감정/동작 기반 애니메이션. 
- **장기**: 프로그램별 파인튜닝, 대규모 평가 데이터 구축, 실시간 스트리밍 대응.

## 9. 실행 가능한 워드 자막 생성 프로그램
`generate_captions.py`는 분석된 컷/자막 후보(JSON), 선택적 프로그램 대본·용어 사전(JSON), 프로그램 자막 테마(JSON)를 받아 `.docx` 워드 파일을 생성한다. `python-docx`를 사용하며, 기본 스타일은 고딕/고딕 중앙/중앙대판/굴림을 포함한다.

### 9-1. 입력 JSON 스키마(요약)
```jsonc
{
  "clips": [
    {
      "text": "고딕) 1라운드를 향한 기묘한... 첫 걸음",   // 자막 본문
      "subtitle_type": "말|상황|재미",                 // 미지정 시 "말"
      "sequence_tag": "intro|build|peak|payoff",       // 빌드업 흐름 태그
      "tone_pack": "런닝게임",                          // 톤/밈 팩 이름
      "font": "고딕|고딕 중앙|중앙대판|굴림",          // 없으면 subtitle_type으로 자동 매핑
      "align": "left|center|right",                    // 없으면 스타일 기본값
      "size": "small|medium|large",                    // 없으면 스타일 기본값(고딕 20pt 등)
      "notes": "PD guide kept",                        // 메모(페르소나 검수/보조 정보)
      "keep_original": true,                            // PD 가이드 고정 여부
      "hook": true,                                     // 쇼츠/훅 표시
      "cta": false,                                     // CTA 표시
      "theme_applied": "running_show_v1"               // 적용한 테마 ID
    }
  ]
}
```

### 9-2. 자막 테마 JSON 예시
```json
{
  "style_id": "running_show_v1",
  "styles": {
    "말": {"font": "고딕", "align": "left"},
    "재미": {"font": "고딕 중앙", "align": "center", "size": "medium"},
    "상황": {"font": "굴림", "align": "right", "size": "small"}
  }
}
```

### 9-3. 프로그램 대본/용어 사전 JSON 예시
```json
{
  "names": [{"label": "맏형", "alias": ["큰형", "형님"]}, "MC"],
  "terms": ["런닝볼", "숨바꼭질"]
}
```

### 9-4. 설치 및 실행 예시
```bash
pip install -r requirements.txt
python generate_captions.py \
  --analysis sample_data/analysis.json \
  --lexicon sample_data/lexicon.json \
  --theme sample_data/theme.json \
  --output captions.docx
```
실행 후 워드 파일에는 자막 스타일(고딕/고딕 중앙/중앙대판/굴림)과 숨김 메타데이터(`subtitle_type`, `sequence_tag`, `tone_pack`, `hook`, `CTA`, `keep_original`, `notes`, `theme`)가 함께 기록되어 PD 가이드 자막 보존, 빌드업 검수, 프로그램 테마 적용 여부를 추적할 수 있다.

### 9-5. 빠른 로컬 테스트 절차
1) **의존성 설치**: `pip install -r requirements.txt`로 `python-docx`를 설치한다. (프록시 등 네트워크 제약이 있으면 미리 받은 `python_docx-*.whl` 파일을 두고 `pip install python_docx-*.whl`로 설치할 수 있다.)
2) **샘플 실행**: 저장소 루트에서 아래 명령을 실행하면 `captions.docx`가 생성된다.
   ```bash
   python generate_captions.py \
     --analysis sample_data/analysis.json \
     --lexicon sample_data/lexicon.json \
     --theme sample_data/theme.json \
     --output captions.docx
   ```
3) **결과 확인**: `captions.docx`를 열어 폰트/정렬/크기가 입력 데이터(`subtitle_type`, `font`, `align`, `size`)에 맞게 적용됐는지 확인하고, 각 문단 코멘트에 `subtitle_type`, `sequence_tag`, `tone_pack`, `hook`, `cta`, `keep_original`, `notes`, `theme` 메타데이터가 있는지 검수한다.
4) **자체 데이터로 교체 테스트**: `sample_data/analysis.json`을 본인 분석 결과로 교체하거나, `--lexicon`/`--theme` 인자를 생략해 폴백 스타일을 확인할 수 있다. 경로를 잘못 넣었을 때의 에러 메시지로 유효성 검사 여부를 확인해볼 수 있다.
